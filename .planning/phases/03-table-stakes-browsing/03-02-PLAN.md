<objective>
Give Talaria bookmarks: a toolbar star (Ctrl+D) toggles the current page bookmarked, a Bookmarks
panel (Ctrl+B) lists and lets the user revisit or remove them, and the list survives a restart —
BROWSE-02.

Purpose: the second plan in Phase 3's sequential chain (see 03-01's objective for why the four
plans cannot share a wave — every one of them touches `app.rs` and `gui.rs`). This plan extends the
`ChromePanel` enum 03-01 established with one more variant and follows the exact same panel
mechanism, so the marginal cost of Bookmarks is genuinely additive: a new store module (this time
the direct, un-diverged `vault.rs` CRUD shape — bookmarks are low-churn, unlike history), one new
toolbar button pair (a list panel plus a standalone toggle), and one new `UiAction`.

Output: `bookmarks.rs`, `ChromePanel::Bookmarks`, the bookmark-star toggle and Bookmarks-list panel
in the chrome, and `tests/e2e/bookmarks_test.py` proving the toggle and restart survival through the
real binary driven via `xdotool` (bookmarking is a human-only chrome action with no raw-socket
command — unlike history capture, which rides real navigation, this has to be driven the way
`keyboard_nav_test.py` drives Ctrl+T/Ctrl+L/Ctrl+W).
</objective>

`Vault::upsert`/`Vault::delete` (`crates/talaria-shell/src/vault.rs:440-470`) are the direct CRUD
shape to copy, `url` as the identity key instead of `(host, username)`:
```rust
pub fn upsert(&mut self, entry: CredentialEntry) {
    let host = entry_host(&entry.url);
    let existing = host.and_then(|host| {
        self.entries.iter().position(|candidate| {
            candidate.username == entry.username
                && entry_host(&candidate.url).is_some_and(|candidate| candidate == host)
        })
    });
    match existing {
        Some(index) => self.entries[index] = entry,
        None => self.entries.push(entry),
    }
    self.save();
}
```
and `delete`'s `retain` + length-diff pattern (`crates/talaria-shell/src/vault.rs:457-470`).

`vault.rs`'s `save()` (`crates/talaria-shell/src/vault.rs:414-428`) does a plain `fs::write` —
**do not copy this line for bookmarks.** Per `03-PATTERNS.md`'s "Shared Patterns" / "Store module
shape" section, every one of Phase 3's four new stores upgrades this to write-to-temp
(`<path>.tmp`, same directory) + `fs::rename`, applied uniformly even to low-churn stores because it
costs nothing extra. Bookmarks is this plan's first store to actually use that upgraded shape (03-01's
`history.rs` reserves temp+rename for its rare cap-prune path only, since its per-navigation write is
a cheap append, not a rewrite — bookmarks has no such distinction: every mutation *is* a whole-array
rewrite, so every mutation goes through temp+rename).

The toolbar button pattern (`crates/talaria-shell/src/gui.rs:225-239`, the `KEY` button) and the
panel-open gate the History panel established in 03-01 (its own `else if panel == ChromePanel::History`
branch, sibling to the credentials `if` and the crashed-tab `else if`) are the two things to extend,
not re-derive.

`handle_browser_shortcut`'s character-match arm (`crates/talaria-shell/src/app.rs`, the `"k"`/`"h"`
arms after 03-01) has no existing `"b"` or `"d"` binding — confirmed by 03-01's own SUMMARY and the
original grep of that arm (only `l`, `k`, `t`, `w`, `r` existed pre-Phase-3; `h` was 03-01's
addition). `b` and `d` are free.

The e2e driving mechanism (`tests/e2e/keyboard_nav_test.py`, read in full): `xdotool search --name
Talaria` to find the window id, `xdotool windowfocus --sync <id>`, then `xdotool key ctrl+d` etc.,
with `time.sleep(...)` settling between actions and a raw-socket `tabs_list` poll to observe state
changes — this suite's shape is the template for `bookmarks_test.py`.

    Create `crates/talaria-shell/src/bookmarks.rs` with a `//!` module header stating: plaintext, not
    a secret, a small user-curated flat list (not capped, not append-only — mutations rewrite the
    whole array, same shape as `vault.rs` but without encryption).

    Define `Bookmark { pub url: String, pub title: String, pub created_at_ms: u64 }` and `Bookmarks {
    path: PathBuf, entries: Vec&lt;Bookmark&gt; }`. Add a private `config_dir()` copy (same four lines as
    `history.rs`'s — do not share a module for this; each store owns its own copy, per 03-01's
    precedent and RESEARCH.md's explicit permission to duplicate rather than extract).

    `load()`: `fs::read(&path).ok().and_then(|data| serde_json::from_slice(&data).ok()).unwrap_or_default()`
    — the exact degrade-never-abort idiom `vault.rs`'s `load()` and RESEARCH.md's own Bookmarks
    example use; a corrupted file becomes an empty list, silently, per `03-UI-SPEC.md`'s Copywriting
    Contract ("No user-facing copy" for store load failures).

    `is_bookmarked(&self, url: &str) -> bool`: `self.entries.iter().any(|b| b.url == url)`.

    `upsert(&mut self, url: String, title: String, created_at_ms: u64)`: if `!self.is_bookmarked(&url)`,
    push a new `Bookmark` and call `self.save()`; if already bookmarked, do nothing (no-op, no
    write) — the caller decides whether to call `upsert` or `remove` based on the current state, this
    method itself is not the toggle.

    `remove(&mut self, url: &str) -> bool`: `retain` + length-diff, exactly like `Vault::delete`'s
    shape, calling `self.save()` only when something changed, returning whether it did.

    `entries(&self) -> &[Bookmark]`: borrowed accessor, matching `History::entries`'s shape from
    03-01.

    `save(&mut self)`: serialize `self.entries` to JSON, ensure the parent dir exists
    (`fs::create_dir_all`), write to `self.path.with_extension("json.tmp")` (or an equivalent
    same-directory temp name — `bookmarks.json.tmp`), then `fs::rename` that temp path over
    `self.path`. On any I/O error at either step, `log::warn!` and return — never panic, matching
    `vault.rs`'s degrade posture for a save that cannot land.

    Add `#[cfg(test)] mod tests` at `vault.rs`'s density: load on missing file is empty; upsert then
    load (fresh instance) round-trips; upsert twice on the same URL leaves exactly one entry;
    is_bookmarked reflects upsert/remove correctly; remove of an absent URL returns false and does
    not write; remove of a present URL returns true, persists, and a subsequent load no longer has
    it; a corrupted (non-JSON) file loads as empty without panicking.

    Add `mod bookmarks;` to `crates/talaria-shell/src/main.rs`, alphabetically after `bookmarks` (i.e.
    before `control`).
