<objective>
Give the shell a Streamable-HTTP MCP listener: **off by default**, bound to `127.0.0.1` and nothing
else, on its own thread, reaching the browser only through the `EventLoopProxy` — with the Access
panel that turns it on and the toolbar indicator that says whether it is on.

Purpose: AUTH-03, and the substrate SC 1 and SC 4 are proven against. This is the plan that opens a
network port in a process holding an encrypted credential vault and a logged-in browsing session,
which `04-RESEARCH.md` calls the largest attack-surface increase in the project's history — so
D-04-04's two constraints are load-bearing here, not stylistic.

**The listener this plan ships cannot be driven.** Authentication arrives in 04-05 and 04-06; a
listener that accepted requests in the meantime would be threat T-1 shipped and unmitigated, on a
port every local account can reach. So `http.rs` attaches an interim authorization provider that
refuses every credential unconditionally and declares no OAuth endpoints. The transport is real,
the framing is real, the thread and the shutdown are real — and nothing can call a tool through it
until 04-05 replaces that provider. SC 1's "drives the same tool surface" is therefore proven in
04-05, against a seeded token store, and this plan's suite proves the complementary half: that with
no credential, nothing happens.

`04-RESEARCH.md`'s Q2 alternative — a `talaria-mcp --serve` mode proxying over the existing Unix
socket — is rejected and worth saying so: it fails on lifecycle (nothing starts it, nothing reports
that it died), on the consent round trip (a control-socket command existing purely to raise a UI
panel), and on revocation latency, since the proxy would re-read the token file per request anyway,
at which point the process split buys nothing.

Output: `http.rs`, the `remote_access` config key, `Shared::remote`, `ChromePanel::Access`'s status
half, the toolbar connection glyph, `parse_agent_url`'s own-origin refusal, and
`tests/e2e/http_transport_test.py`.
</objective>

**The thread-spawn precedent** (`crates/talaria-shell/src/control.rs:78-89`):

```rust
pub fn spawn(proxy: EventLoopProxy<AppEvent>) {
    std::thread::Builder::new()
        .name("talaria-control".into())
        .spawn(move || {
            let runtime = tokio::runtime::Builder::new_current_thread()
                .enable_all()
                .build()
                .expect("control socket runtime");
            runtime.block_on(serve(proxy));
        })
        .expect("spawn control thread");
}
```

Two deliberate divergences, both to be stated in `http.rs`'s own comments: this thread is named
`talaria-http` and builds `new_multi_thread` (the control socket must never be starved by an HTTP
request, and `rust-mcp-axum` expects a full tokio), and `http::spawn` is called **conditionally** —
only when the listener is enabled — where `control::spawn` is unconditional at startup, so a default
install pays nothing.

**The request round trip to copy** (`crates/talaria-shell/src/control.rs:241-272`): build an
`AgentRequest`, `proxy.send_event(AppEvent::Agent(request))`, await the `oneshot` under
`tokio::time::timeout(command_timeout_secs())`, and turn each of the three outcomes into a reply.
The in-process `CommandSink` is that block minus the socket framing. `AgentRequest` is already
public (`control.rs:20-25`) with fields `session_id`, `client`, `command`, `reply`.

**Session identity for HTTP callers.** `AgentRequest.session_id` is a `u64` the control socket
allocates from `static NEXT_SESSION: AtomicU64` (`control.rs:26`). HTTP callers need ids from the
same counter so a tab's owner is unambiguous — expose a small `pub fn next_session_id()` in
`control.rs` rather than adding a second counter, and say in its doc comment that two allocators
would eventually collide and silently give one client another's tabs. This is the only change
`control.rs` takes in this plan; `peer_uid_ok` and its call site are untouched.

**The proxy-clone-before-spawn rule** (`crates/talaria-shell/src/app.rs:1852-1856`): `Shared` is
`Rc`-based and not `Send`, so the closure can never borrow it and the proxy is the whole of what
crosses the thread boundary. `Shared::event_proxy` (`app.rs:114`) already exists and its doc comment
already narrates being "the third holder of an `EventLoopProxy`" — the HTTP listener makes it the
fourth. Update that comment.

**`parse_agent_url` today** (`crates/talaria-shell/src/app.rs:1476-1492`) takes `&str` and returns
`Result<Url, String>`, holding the parse to `agent_scheme_allowed` (`app.rs:1467`). It gains a
second parameter carrying the bound `host:port`, or nothing when nothing is bound. Both call sites
are inside `execute_agent_command` (`Command::TabsOpen` and `Command::Navigate`), which already has
`state`. The refusal's wording follows `validate_download_filename` (`app.rs:1510-1523`), whose
docstring explains why each refusal is worded separately.

**Settings' validated-not-parsed gate** (`crates/talaria-shell/src/settings.rs:208-224`) is the
direct analog for a bind address read off disk, including its "arrived by the back door" paragraph.
One critical adaptation: today a bad value returns `Self::defaults_at(path)`, resetting the *whole*
settings object. A bad `remote_access` key must degrade **that key only** to disabled and leave
`search_engine` alone — resetting a person's search engine because they mistyped a port is a
different bug.

**Settings' save-still-applies property** (`settings.rs:228-241`): a write that cannot reach disk
still applies to the session. Carry it in the safe direction only — turning the listener *off*
applies immediately whether or not the write lands; turning it *on* when the write fails is the
riskier failure, so state which was chosen and why in the code comment.

**Panel and toolbar patterns**: `ChromePanel` (`gui.rs:26-40`), `UiAction` and its "even this goes
through the round trip" rule (`gui.rs:53-68`), `Gui::set_panel`'s reset-everything discipline
(`gui.rs:409-424`), the toolbar-button-plus-rect shape (`gui.rs:682-700`), `record_rect`
(`gui.rs:187`) and why the absence of the collection is the off switch (`gui.rs:176-204`), and the
arm-then-confirm control (`gui.rs:1240-1273`) with its two rect names for one control.

**Pinning the protocol revision on the second transport.** D-04-01 locks this phase to the MCP
revision `rust-mcp-sdk 1.0.1` implements, and the stdio binary pins it explicitly in its
`server_details` (`crates/talaria-mcp/src/main.rs`). A second transport that took the SDK's default
would be one dependency bump away from negotiating a different revision than stdio while every test
still passed — 04-05's `tools/list` parity compares the tool *surface*, not the version. So the
listener's `server_details` sets the revision from the **same constant the stdio binary uses**,
rather than repeating the literal: expose it from `talaria_mcp`'s library root (04-01 made that
crate a library precisely so both transports share one definition) and have both call sites read it.
That is a one-line addition to `crates/talaria-mcp/src/lib.rs` and a one-line change at the stdio
call site.

**The one manifest edit this plan owns.** 04-02 landed every other dependency but deliberately did
not add the `talaria-shell` → `talaria-mcp` edge, because 04-02 and 04-01 run in the same wave and a
path dependency on a library target 04-01 had not finished creating would have raced. This plan is
the first that depends on both, so it adds exactly two lines:
`talaria-mcp = { path = "crates/talaria-mcp" }` in the root `Cargo.toml`'s
`[workspace.dependencies]`, beside the existing `talaria-protocol` path line, and
`talaria-mcp = { workspace = true }` in the shell's `[dependencies]`. Then re-confirm the lockfile
pin exactly as 04-02 did — a path dependency resolves nothing new from the registry, so the diff
should be a single added package entry, and anything larger means something else re-resolved.

**Shared file coordination.** `crates/talaria-shell/src/main.rs` is edited by this plan (adding
`mod http;`) and by 04-04 (adding `mod agents;`) in the same wave. Each adds exactly one line to the
alphabetical `mod` list — `agents` before `app`, `http` after `history`. Re-read the file
immediately before editing and insert the single line with a scoped edit; do not rewrite the file.

One consequence to expect rather than chase: this plan's gates run
`cargo clippy --all-targets --locked -- -D warnings` over the **whole workspace**, so once the
sibling plan lands its own `mod` line the gate also compiles that plan's in-progress module. A
clippy failure whose diagnostics point at the sibling's file is the sibling's to fix, not a
regression this plan introduced — do not edit that file to make this plan's gate pass.

**Port choice, decided here** (`04-CONTEXT.md` left "fixed vs ephemeral" open and asked the transport
plan to decide and say why): a **fixed, configurable** port with a default of **8779**. Fixed,
because an MCP client is configured with a URL by a human once, and an address that changes every
launch makes that impossible; the address the UI shows is the one the listener reported back, so a
future ephemeral mode would need no copy change. **8779** rather than the SDK's `8080` because 8080
collides with essentially every local development server, and rather than anything in `32768-60999`
because that is this machine's ephemeral port range (`/proc/sys/net/ipv4/ip_local_port_range`) where
a transient outbound connection can already hold the port. Also not any of the common framework
defaults — 3000, 4200, 5000, 5173, 8000, 8081, 9000. The e2e suites do not hardcode it; the harness
picks a free port and writes it into `config.json`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated network peer → the shell | **New party.** Anything that can open a TCP connection to the listener, including every other local user account and every page in every browser on the machine. It was previously impossible for such a party to exist |
| local web page → the MCP endpoint | A page can issue a cross-origin request whether or not it can read the response; the endpoint must refuse it before any browser state is touched |
| `talaria-http` thread → the winit main thread | The fourth off-main-thread actor; `Shared` is `Rc`-based and not `Send`, so only an `AppEvent` crosses |
| an agent's own `evaluate` → Talaria's auth endpoints | `http` is in the agent navigation allowlist, so an agent can point a tab it owns at the listener unless refused |
| a hand-edited `config.json` → the bind address | A settings file is not a trusted input; it is the back door the Settings panel's validation exists to close |
