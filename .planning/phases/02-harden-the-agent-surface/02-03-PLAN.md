<objective>
Close SEC-01: another local user cannot drive the browser.

Purpose: `UnixListener::bind` never chmods the socket, and `handle_connection` accepts any `client`
string with no credential check. On the fallback path — a bare `/tmp/talaria-$UID.sock` — any local
user can connect, send hello, and get full control of the browser: the user's cookies, their live
sessions, arbitrary JavaScript in logged-in pages, and the credential vault through `cookies_read`.

Scope, stated explicitly: this is local IPC hygiene, stopping a *different OS user* from driving the
browser. It is deliberately not the per-agent permission scoping that PROJECT.md rules out of scope.

Output: A `SO_PEERCRED` gate on accept, a mode-0600 socket inside a mode-0700 per-UID directory on
the fallback path, and Python suites that resolve the socket path the same way the Rust does.
</objective>

Path construction to change (`crates/talaria-protocol/src/lib.rs:13-27`) — note the deliberate libc
shim comment; the same shim serves the per-UID directory:

```rust
/// Default socket location: `$XDG_RUNTIME_DIR/talaria.sock`, falling back to
/// `/tmp/talaria-$UID.sock`.
pub fn socket_path() -> PathBuf {
    if let Ok(dir) = std::env::var("XDG_RUNTIME_DIR") {
        return PathBuf::from(dir).join("talaria.sock");
    }
    let uid = unsafe { libc_getuid() };
    PathBuf::from(format!("/tmp/talaria-{uid}.sock"))
}

// Tiny libc shim so we don't pull the libc crate for one call.
extern "C" {
    #[link_name = "getuid"]
    fn libc_getuid() -> u32;
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| other local OS users -> control socket | Untrusted; today they can connect, handshake, and drive the browser on the fallback path |
| filesystem -> socket path | The socket file and its directory are the only access control that exists before the peer check |
| kernel `SO_PEERCRED` -> `peer_uid_ok` | The identity assertion the gate is built on |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-03-01 | Spoofing | control socket hello handshake | high | mitigate | `peer_uid_ok` compares the kernel-reported peer UID against the shell's UID on every accept, before any session id is allocated; the self-asserted client string is no longer the only identity |
| T-02-03-02 | Information Disclosure | fallback socket in the shared temp dir | high | mitigate | Socket moves into a per-UID directory created at mode 0700, and the socket itself is chmodded 0600 with the result checked |
| T-02-03-03 | Elevation of Privilege | credential lookup failure admitted as trusted | high | mitigate | The helper fails closed: a peer whose credential cannot be read is rejected, not admitted |
| T-02-03-04 | Denial of Service | one rejected peer stalling the accept loop | medium | mitigate | The check runs synchronously on the accepted stream and the loop continues immediately; per-connection handling stays in its own spawned task |
| T-02-03-05 | Tampering | pre-existing socket file or directory owned by another user | high | mitigate | The existing remove-then-bind sequence is preserved and the 0700 directory creation is checked; failure to establish either is an error-level log and a refusal to serve |
| T-02-03-06 | Repudiation | silent rejection with no operator signal | low | mitigate | Every rejection logs at warn level naming both UIDs |
| T-02-03-07 | Information Disclosure | rejection message leaking shell details to the peer | low | mitigate | Nothing is written back to a rejected peer; it observes only a closed connection |
| T-02-03-08 | Tampering | package installs | n/a | accept | No npm/pip/cargo package is installed and no dependency is added; no legitimacy gate applies |

ASVS level 1; block on high. T-02-03-01, -02, -03 and -05 are high and all mitigated.
</threat_model>
