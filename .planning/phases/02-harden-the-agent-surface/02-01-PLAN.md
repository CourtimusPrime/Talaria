```python
def _pid_alive(pid):
    """True for a live process; False for none or a zombie (killed but not
    yet reaped by its parent — still listed in /proc)."""
    try:
        with open(f"/proc/{pid}/status") as f:
            for line in f:
                if line.startswith("State:"):
                    return "Z" not in line.split()[1]
    except OSError:
        return False
    return False
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo working tree -> git commit | The pre-commit hook is the only automated gate between two concurrent sessions and a corrupted commit history |
| lock file -> acquire/check | `.overnight-lock` is attacker-writable by anyone who can write the repo dir, and its `pid` field is now trusted for a liveness decision |
| host `/proc` -> `_pid_alive` | PID reuse means a recycled PID can make a stale lock look live |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01-01 | Spoofing | `acquire` pid field | medium | mitigate | The recorded PID is the caller's parent (or an explicit `--pid`), not a self-reported identity from a third party; `pid_source` records which, so a reader can see when the default was used |
| T-02-01-02 | Tampering | `.overnight-lock` | low | accept | The file is a cooperative marker in a single-user working tree; anyone able to edit it can already edit the repo. Documented in the module docstring |
| T-02-01-03 | Denial of Service | `check` in pre-commit | medium | mitigate | The hook fails open (exit 0 with a stderr warning) only for a missing python3 or missing script, so a broken environment cannot permanently block commits; every other non-zero status blocks |
| T-02-01-04 | Repudiation | stale-clear path | low | mitigate | Clearing a stale lock prints the previous owner and pid on its own line, so takeover is visible in the loop transcript rather than silent |
| T-02-01-05 | Elevation of Privilege | PID reuse in `_pid_alive` | low | accept | A recycled PID makes a stale lock look live, which fails safe (refusal) rather than unsafe (silent takeover). Recovery is the existing explicit force flag |
| T-02-01-06 | Tampering | package installs | n/a | accept | This plan installs no npm/pip/cargo packages and adds no dependency; no legitimacy gate applies |

ASVS level 1; block on high. No high or critical threat is present in this plan.
</threat_model>
