<objective>
Close MCP-09: an agent cannot reach the local filesystem, or any other non-web scheme, through
`navigate` or `tabs_open`.

Purpose: `parse_agent_url` accepts anything `url::Url::parse` accepts. `file://` goes straight
through to a real `WebView::load`, and the agent then reads the loaded document with `evaluate` —
i.e. exfiltrates any file the user can read that Servo will render. `resolve_location`, the human
omnibox path, is already a separate function, so restricting agents costs the user nothing.

Output: A scheme allowlist enforced at the single agent-URL chokepoint, a message-shaped refusal
that names the offending scheme, and an e2e suite that proves both the refusal and the untouched
human path.
</objective>

The single function to change (`crates/talaria-shell/src/app.rs:838-849`):

```rust
/// Agent-supplied URLs: accept scheme-less hosts ("example.com") by assuming
/// https, but never fall back to a search query — an agent that meant to
/// search should do so explicitly.
fn parse_agent_url(input: &str) -> Result<Url, url::ParseError> {
    match Url::parse(input) {
        Ok(url) => Ok(url),
        Err(url::ParseError::RelativeUrlWithoutBase) if !input.contains(' ') => {
            Url::parse(&format!("https://{input}"))
        },
        Err(error) => Err(error),
    }
}
```

Its two call sites, both of which format the error identically today:
- `Command::TabsOpen` — `crates/talaria-shell/src/app.rs:914-927`, a plain `match parse_agent_url(&url)`
- `Command::Navigate` — `crates/talaria-shell/src/app.rs:948-967`, a tuple match
  `match (webview_for(tab_id), parse_agent_url(&url))` with arms in the order
  `(Ok, Ok)`, `(Err(outcome), _)`, `(_, Err(error))`

Both currently end in:
```rust
Err(error) => {
    let _ = reply.send(Outcome::Error { message: format!("bad url: {error}") });
},
```

The human path, which must remain byte-identical (`crates/talaria-shell/src/app.rs:851-868`):
`pub fn resolve_location(input: &str) -> Url` — parses, accepts a scheme with a host or the `about`
scheme, tries an https prefix for dotted input, and otherwise builds a DuckDuckGo query URL.

The `about:blank` constraint: popup adoption registers the literal string at
`crates/talaria-shell/src/app.rs:1316` (`tabs.register(..., "about:blank".into(), ...)`) and
`notify_url_changed` compares `url.as_str() != "about:blank"` at `crates/talaria-shell/src/app.rs:1374`.
The allowlist must admit that exact string, not the whole `about` scheme.

House error style (`.planning/codebase/CONVENTIONS.md`): agent-facing failures are `Outcome::Error`
values, lowercase, no trailing period, cause after a colon or in parentheses, inline format captures.
`crates/talaria-shell/src/app.rs` contains zero `unwrap()` calls — keep it that way.

The e2e suite shape to copy whole (`tests/e2e/crash_event_test.py`): module docstring, `conn(name)`
helper doing the hello handshake over `AF_UNIX`, a global-`rid` `rpc(f, command, **params)` that
loops until its own reply id comes back, bare asserts passing the whole reply as the message, and a
final `print("... CHECKS PASSED")` sentinel. Terse variable names are sanctioned here.

  <action>
    Change `parse_agent_url`'s return type from `Result<Url, url::ParseError>` to
    `Result<Url, String>`. A scheme refusal is not a parse error, so the error channel has to carry a
    message rather than a `url::ParseError`.

    Keep the existing parse behaviour intact: a URL that parses is taken as-is; a
    `RelativeUrlWithoutBase` failure on input containing no space retries with an https prefix; any
    other parse failure is returned. Map every parse failure to the string
    `format!("bad url: {error}")` so the wire-visible message for malformed input is unchanged from
    today — the e2e suites assert on it.

    After a successful parse, apply the allowlist. Add a private helper
    `fn agent_scheme_allowed(url: &Url) -> bool` directly above `parse_agent_url` with a doc comment
    explaining each admission: `http` and `https` are the web; `data` grants an agent nothing it
    cannot already produce through `evaluate`; and the blank page is admitted by exact string match
    on `url.as_str()` rather than by scheme, because popup adoption registers and compares that exact
    literal and admitting the whole scheme would widen the surface to the engine's internal pages.
    Everything else — the local filesystem scheme, the script pseudo-scheme, object URLs, and any
    custom scheme Servo may register — returns false.

    When the helper returns false, return
    `Err(format!("scheme {} is not allowed for agents — use http, https, data:, or about:blank", url.scheme()))`.
    The message names the rejected scheme, is lowercase, and has no trailing period, per conventions.

    Update both call sites. `Command::TabsOpen` becomes
    `Err(message) => { let _ = reply.send(Outcome::Error { message }); }`. `Command::Navigate` keeps
    its tuple match and arm ordering exactly as it is — only the third arm changes from
    `(_, Err(error))` formatting a `ParseError` to `(_, Err(message))` forwarding the String
    unchanged. Preserve the trailing comma after each block match arm; rustfmt will not add it.

    Do not touch `resolve_location`. Its behaviour for a user-typed non-web URL is the deliberate
    counterpart to this change (D-02), and no opt-in setting to relax the agent allowlist is added in
    this phase (D-03).
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client -> control socket -> `parse_agent_url` | Fully untrusted agent-authored string crosses into a real engine navigation |
| `parse_agent_url` -> `WebView::load` | Once past the allowlist the URL is loaded with full page authority in a shared cookie jar |
| human omnibox -> `resolve_location` | Deliberately unrestricted; the user is the trust root, not a subject of policy |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-02-01 | Information Disclosure | `parse_agent_url` local-filesystem scheme | high | mitigate | Allowlist admits only http, https, data, and the exact blank-page string; every other scheme returns `Outcome::Error` before `WebView::load` is reached. Proved by `tests/e2e/scheme_refusal_test.py` |
| T-02-02-02 | Elevation of Privilege | script pseudo-scheme via navigate | high | mitigate | Same allowlist; the script pseudo-scheme is not admitted, so an agent cannot run script in a document it did not already have an evaluate handle on |
| T-02-02-03 | Information Disclosure | object-URL scheme reaching engine-internal resources | medium | mitigate | Not admitted by the allowlist |

| T-02-02-06 | Denial of Service | refusal path leaving a half-navigated tab | low | mitigate | Refusal happens before `webview.load`; the e2e suite asserts the tab's url is unchanged after a refused navigate |
| T-02-02-07 | Tampering | package installs | n/a | accept | No npm/pip/cargo package is installed and no dependency is added; no legitimacy gate applies |
