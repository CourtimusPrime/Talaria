<objective>
Close MCP-10: a heavy-JS page that wedges its own `evaluate` converts a thirty-second stall into an
instant, actionable error, and the human's route back into that tab stays open.

Purpose: on JS-heavy sites every `evaluate` — even reading the document title — burns the full command
timeout, because Servo's script thread is busy with the page's own JavaScript and never runs the
callback. The blanket timeout is the only defence and there is no per-tab isolation. The real fix is
upstream, a slow-script interrupt exposed through libservo, and is out of scope. What is in scope is
refusing the second call instantly instead of making the agent wait for a timeout it is going to get
anyway.

The `wrap_script` trampoline is explicitly off-limits this phase: it depends on the engine's exact
error taxonomy and error-message wording, and MCP-10 is solved by tracking outside it.

Output: A per-tab in-flight set on `Shared`, a distinct busy error, a deadline that self-heals a lost
callback, and an e2e suite that proves both the refusal and the surviving takeover route.
</objective>

| Boundary | Description |
|----------|-------------|
| agent script -> Servo script thread | Fully untrusted JavaScript that can refuse to yield, which is the condition this plan bounds |
| Servo evaluate callback -> `Shared` | Reentrant: the callback runs while the engine holds internal borrows, so a completion signal must not need one |
| in-flight registry -> command dispatch | The registry decides whether an agent's request is served or refused |
