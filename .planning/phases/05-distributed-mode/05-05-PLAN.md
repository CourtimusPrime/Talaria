<objective>
Put the view channel on the listener that already exists, and close the defect that would otherwise
ship with it.

Purpose: `05-PATTERNS.md` found the load-bearing fact of this phase by reading the router. Phase 4's
`build_router` applies the origin-and-host refusal as the **outermost** axum layer, with a comment
saying so — *"so it runs first and covers every route this process serves"* — and a route merged into
that router inherits it for free. That is worth a lot here, because WebSockets are not subject to the
same-origin policy and have no preflight: origin enforcement is entirely the server's job, and
forgetting it is what cross-site WebSocket hijacking is. Talaria's outermost layer closes it by
construction, in the strictest possible direction: a browser **always** sends an origin header, so a
browser client can never connect, and the native-only remote viewer is now enforced by middleware
rather than merely chosen.

But the same reading found the trap. The `AuthMiddleware` chain is handed to `McpHttpHandler`, and
the SDK composes it **only for its own transport handlers**. A merged axum route does **not** pass
through it — which is the entire reason the origin refusal was lifted out to an axum layer in the
first place. So a naively mounted view route would be origin-checked and **unauthenticated**: exactly
the class of defect Phase 4 shipped as CR-01 and found in review. Caught here at planning time
instead, which is worth nothing unless the acceptance criteria prove authentication on this route
*directly* rather than assuming inheritance. They do.

The second thing this plan must not leave for later is revocation. Verification runs per request, and
a WebSocket has no next request to fail. `04-08` spent a whole plan closing that for the legacy event
stream, and the lesson it recorded is about the *assertion*, not the mechanism: a test that issues a
fresh request and watches it fail passes whether or not the stream ever closed. This plan registers
the socket for termination and asserts closure **from the client end**.

Output: a `/view` route with its own bearer check, a view session table on the main thread that can
list and attach to agent tabs and nothing else, a standard-library WebSocket client in the harness,
and the end-to-end suite that pins all of it. No frames yet and no input yet — those are 05-08 and
05-06.
</objective>

<interfaces>
**Where the route mounts, and why it matters** (`http.rs:1146-1166`). `mcp_routes(...)` builds the
router and two `.layer(...)` calls wrap it: the stream-connection note, then the origin-and-host
refusal **outermost**. The view route is merged into the `mcp_routes` result **before** both, so it
inherits both. Do not add a third layer for it and do not reorder the two that exist.

**The correction, stated once so it cannot be missed.** The middleware vector at `http.rs:1101-1106`
— the origin refusal, the DNS-rebinding protector, the auth middleware and the identity note — is
handed to `McpHttpHandler`. The SDK composes it for the transport handlers it dispatches, and
`build_router`'s own comment at 1156–1160 says why the origin refusal had to be lifted out: *"that
chain is reachable only from the transport handlers."* The same sentence applies to the auth
middleware, and it is the half nobody wrote down. **The view route calls the shared authorization
provider itself.**

Concretely: pull the bearer credential off the upgrade request, call the same provider handle
`build_router` constructs, and refuse on anything but success. Audience is compared byte for byte
inside that provider against the canonical resource — **do not add a second comparison.** A viewer
token minted for a different resource is already refused by code Phase 4 wrote and 05-04 re-pointed
at the advertised identity; a second check here would be a second spelling of the same rule, which is
exactly what `canonical_resource`'s doc comment argues against.

**Do not add the view path to the public discovery allowlist.** That array is declared with an
explicit length of two (`http.rs:243`), so adding an entry is a deliberate, visible edit — leave it
at two. The existing test at `http.rs:1682` pins that everything outside those two paths is
origin- and host-checked; extend it to name the view path, so a later refactor that exempted it would
fail a test rather than pass silently.

**Revocation, and the shape of its assertion.** `StreamRegistry` (`http.rs:681`) works over the SDK's
session directory, and `terminate_matching` walks sessions. **A view socket is not an SDK session**,
so it cannot be reached that way. Give the registry a second half: a table of close handles keyed by
the **verified client id**, registered when a socket is accepted and removed when it ends normally,
so a completed connection leaves nothing behind. `terminate_client` closes both halves in the same
call; the shutdown path closes everything. The registry's existing doc comment already explains why
the whole mechanism exists — a revocation that only stopped new requests would leave a revoked agent
still receiving from the browser while the panel showed the row gone — and this is that same failure
in a new shape.

`tests/e2e/revocation_test.py`'s `closed_within` method (271–320) is verbatim what the new assertion
needs, and its docstring says why: *"Asserting instead that a fresh request now fails would pass
whether or not the stream ever closed."*

**What crosses the thread boundary.** `Shared` is `Rc`-based and not `Send`; the only route from the
listener thread to the engine is an `AppEvent` on a cloned `EventLoopProxy`, and `user_event` is the
only place that route lands (`app.rs:126-143`, and the clone-before-spawn at `app.rs:1408-1412`). Add
view variants to `AppEvent` following the existing shape at `app.rs:49-110`: struct variants with
named fields and a doc comment saying what each field means **and what it must never be used for** —
the template being `RemoteListenerBound`'s, which says its address is the one actually bound, *never*
the configured one.

Replies travel back the way `AgentRequest`'s do. A view connection owns a channel; the main thread
pushes acknowledgements, snapshots and (later) frames onto it and the listener thread writes them
out. Nothing on the listener thread touches `Shared`.

**The agent-only lookup, and why it is a lookup rather than a check.** `tabs.rs` already has the
shape: `get` returns an optional reference (223), and `me_tabs` / `agent_tabs` (288–294) are the
precedent for a filtered accessor pair built on `TabOwner::is_agent` (35–37). Add an agent-only
single-tab lookup beside `get`. D-05-02 wants remoting a human-owned tab to be **unrepresentable**
rather than refused after the fact — the same structural shape as the bind constant, and the shape a
threat-model reviewer looks for.

**What a viewer may see, decided deliberately.** `05-RESEARCH.md` Open Question 6 asks whether a
viewer sees every agent's tabs or only its own client's. **Every agent's** — the human is the trust
root, a human viewer is the trust root at a distance, and what they see should match what the local
Agents view shows, which is not session-scoped either. Record it as a decision in the threat register
and in a code comment, because a default reached by reusing an existing listing function is not the
same thing as a decision.

**A stdlib WebSocket client.** The suites are standard-library only. `revocation_test.py:197-213`
already writes a request line and headers by hand onto a raw socket — that is exactly how an upgrade
is sent, with the upgrade and connection headers, a key and the version. Verify the accept value
rather than ignoring it, so a proxy or a server that answered without completing the handshake is
caught. Frame decoding is roughly thirty lines: the two-byte header, the extended-length forms, the
mask bit, and the close, ping and pong control frames. The three-state read primitive
(`revocation_test.py:271-320`) — one read, false on timeout, false-and-ended on an ending — transfers
whole and is what makes "nothing yet, still open" and "ended" distinguishable about the same
connection. **The refusal assertions are cheap precisely because the request is hand-written:** the
origin case and the wrong-host case are one extra line each in the header list.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| an unauthenticated network peer → the view route | Anything that can reach the listener can attempt the upgrade; the bearer token is the entire boundary, exactly as it is for the tool channel |
| a page in any browser → a WebSocket to this server | WebSockets have no same-origin policy and no preflight; origin enforcement is entirely the server's job |
| a revoked client → its already-open view socket | Verification is per request and a socket has no next request; this is where "revoked" can be true of the store and false of reality |
| a viewer → the human's own tabs | The human's Me tabs hold the history rows, the bookmarks and the autofilled credentials; a viewer that could name one has crossed the line D-05-02 draws |
| a refusal → a viewer's model of the tab table | Refusals that differ let a viewer enumerate the human's tabs without ever reaching one |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-02 | Spoofing / Elevation of Privilege | an unauthenticated network peer reaching the view channel | high | mitigate | **The route performs its own bearer verification** against the same provider, because the SDK's middleware chain is composed only for its own transport handlers and a merged axum route does not pass through it — the CR-01-class defect `05-PATTERNS.md` caught by reading the composition at 1101-1106. The end-to-end suite asserts an unauthenticated upgrade is refused **directly** rather than assuming inheritance. The listener remains off by default: no configuration means no thread and no bound port, so the default installation has no view channel at all |
| T-05-01 | Elevation of Privilege | cross-site WebSocket hijacking — a page opening a socket to this server and driving the session | high | mitigate | The origin refusal is the outermost axum layer and the route is merged inside it, so a request carrying an origin header never reaches the handler. A browser always sends one, which closes this by construction and makes a browser-based viewer structurally impossible — a property 05-11 records in `SECURITY.md` so nobody relaxes the layer without knowing what it was load-bearing for. Asserted end to end |
| T-05-09 | Spoofing | a request addressed to a host this server neither bound nor advertises | high | mitigate | The same outermost layer compares against the two-entry enumerated set 05-04 built from configuration. The view path is deliberately **not** added to the two-element discovery allowlist, and the existing routing test now names it among the checked routes, so a later exemption fails a test rather than passing silently |
| T-05-07 | Elevation of Privilege | a revoked viewer keeping its socket and continuing to receive | high | mitigate | The socket registers a close handle under its verified client id at accept time and removes it on normal completion; the same call that terminates a client's SDK streams closes its view sockets, and shutdown closes everything. `revocation_test.py` asserts the closure **from the client end**, which is the assertion 04-08 learned to insist on: a test that issued a fresh request would pass whether or not the socket ever closed |
| T-05-05 | Elevation of Privilege / Information Disclosure | a viewer reaching the human's own tabs | high | mitigate | Resolution goes through an agent-only lookup that yields nothing for a human-owned tab, so remoting one is unrepresentable rather than refused downstream — the structural shape D-05-02 asks for and the one a reviewer looks for. The snapshot is built from the agent-tab iterator, so a human-owned tab never appears in it in any state |
| T-05-05-A | Information Disclosure | a viewer enumerating the human's tabs by watching refusals differ | high | mitigate | Every refusal is one expression with no discriminating field; a unit test compares the human-owned-tab refusal and the no-such-tab refusal **byte for byte**, and the end-to-end suite repeats the comparison over the wire. This follows the established rule that two refusals which differ are two bits an attacker did not have |
| T-05-10 | Information Disclosure | the view channel showing one client's viewer another client's tabs | medium | accept | **Decided rather than defaulted.** A viewer sees every agent's tabs, matching what the local Agents view shows, because the human is the trust root and a remote human is the trust root at a distance. The scope of the acceptance is bounded by who holds a token, which is the same sentence `SECURITY.md` already uses about agents |

| T-05-11 | Denial of Service | a malformed message on an accepted socket wedging the session | medium | mitigate | Structural decoding is 05-03's and returns nothing on anything malformed; this plan's session loop treats a message that did not decode as a closed connection rather than as a value, and the deferred-queue idiom keeps every borrow scoped so a session cannot wedge the loop it reports into |
