<objective>
Give the view channel a vocabulary, in the crate that already owns Talaria's vocabulary — and
correct the claim, made in three places, that this crate is the distributed wire.

Purpose: `05-RESEARCH.md` assessed that claim directly and found it half true. The half that has
held is genuinely valuable: `TabInfo` carries exactly what a remote tab list needs, `Command`,
`Outcome` and `Event` cover the operations, and request/reply correlation by id with out-of-order
replies and unsolicited events on the same stream is already designed for and already exercised
across four phases. Those types go onto the view wire **unchanged**.

The half that has not held is structural. Four of this crate's roughly eleven public items are a
Unix filesystem path and a raw `getuid` shim — none of which mean anything to a peer on another
machine. `Hello`'s client string is the entire identity on that wire, and it is safe only because a
kernel-vouched peer-credential check ran first, which has no TCP equivalent. And there is no frame
channel and no input channel at all: `Command::Screenshot` returns a base64 string inside a
newline-delimited JSON envelope, request/reply, one whole frame per round trip — a screenshot *tool*,
correctly shaped for what it is, and wrong in every dimension for a frame stream.

So this plan adds a `wire` module for what is genuinely new, moves the Unix-only helpers into a
`local` module behind a compilation gate, and rewrites the two module headers that misdescribe the
crate. It changes no existing type and no existing behaviour.

One decision is written into the wire's shape rather than left to a runtime check. **The view
channel carries no `Command`.** Success Criterion 1 says a client can "list, watch and drive" the
server's agent tabs, and D-05-02 reads that literally: the client sees a tab list, receives frames,
and sends input into the page. It does not open tabs, navigate them, evaluate script in them, close
them or download through them. That is not a simplification of the criterion — it is what "drive an
agent's tab" means, it removes an entire second tool surface from the threat model, and a tab a
remote client opened would be a Me tab on the server and therefore not remotely viewable, which
`05-RESEARCH.md` called out as visibly odd. Expressing it as an absence in the enum is what makes it
survive a later reader.

Output: `wire.rs`, `local.rs`, corrected headers, and unit tests at the density the validation map
asks for.
</objective>

<interfaces>
**This crate derives; the shell does not.** `crates/talaria-protocol/Cargo.toml` depends on `serde`
with the derive feature and on `serde_json`, and `lib.rs` uses derives throughout. `talaria-shell`
does **not** depend on `serde` at all and hand-maps everything through `serde_json::Value`. So the
wire types live here and derive; anything the shell defines for itself does not. Keep that boundary
visible — it is the reason the wire types belong in this crate rather than in `http.rs`.

**The tagging convention to copy exactly** (`lib.rs:73-90`, `:143-166`): internally tagged by a
domain-specific key — `type` for `ClientMessage`, `command` for `Command`, `outcome` for `Outcome`,
`event` for `Event` — with `rename_all = "snake_case"`, `#[serde(flatten)]` on a nested envelope, and
`#[serde(default)]` on genuinely optional fields (`lib.rs:200, 217, 219`). The new enums follow the
same shape with their own tag keys.

**The channel layout `05-RESEARCH.md` recommends**, and the reasoning behind each choice:

| Tag | Channel | Payload | Why |
|-----|---------|---------|-----|
| `0x01` | control | JSON view message | Small, infrequent, and worth being able to read by eye |
| `0x02` | tabs | JSON list of `TabInfo` | Reuses the vocabulary unchanged |
| `0x03` | event | JSON `Event` | Same |
| `0x04` | input | JSON input message | Small and infrequent enough that legibility beats bytes |
| `0x10` | frame | fixed binary header, then raw PNG bytes | Kills the base64 inflation and one whole copy |

The gap between `0x04` and `0x10` is deliberate: the low block is human-readable JSON channels and
the high block is binary, so a tag byte tells a reader which world it is in before it decodes
anything.

**The frame header's fields**, each with a job:

- a format version byte, so a client that does not understand a header refuses rather than
  misreading it;
- the tab id the frame belongs to;
- a frame sequence, strictly increasing per connection and per tab;
- a kind discriminating a keyframe from a tile delta;
- the tile's origin and size, and the full frame's size — the second so the client can size its
  texture and detect a viewport change without a separate message;
- a scale denominator, so a half-resolution frame is self-describing rather than requiring the client
  to infer the scale from the size ratio. 05-10's degrade ladder sends half-resolution frames, and a
  client that guessed would guess wrong on an odd-sized viewport;
- **the last input sequence the server had applied when it painted.** This is the field that makes
  input-to-photon latency measurable without a clock synchronised across two machines, and the field
  that lets a client discard a frame that predates its own most recent input. `05-RESEARCH.md` calls
  it out specifically; do not drop it as redundant.

Encode it as a fixed layout with explicit little-endian integer widths and a `to_bytes` /
`from_bytes` pair adjacent to one another, the way `settings.rs` keeps its two mapping functions
adjacent so a field added to one is visibly missing from the other. `from_bytes` takes a byte slice
and returns an optional header: **a slice shorter than the layout produces nothing.** That is the
"truncated header" row in the validation map, and it is asserted here.

**Semantic validation is not this crate's job.** Structural refusal lives here — an unknown tag, a
short header, a missing JSON field, a non-finite coordinate, a tile that claims to exceed its own
frame. Semantic refusal — a coordinate outside a *particular tab's* viewport, a sequence that did not
increase for *this* connection, a key name that maps to nothing, a tab that is not agent-owned —
lives in the shell's `remote_input` module (05-06), because every one of those needs state this crate
does not have. Say so in the module header so the split is deliberate rather than an omission.

**The move, and why not a re-export.** `socket_dir`, `socket_path`, `ensure_socket_dir`,
`current_uid` and the raw `extern "C"` shim (`lib.rs:20-71`) move verbatim into `local.rs` behind a
`#[cfg(unix)]` gate on the module declaration. Do **not** re-export them from the crate root: a
re-export would leave the root's public surface exactly as it is, which is the thing being corrected.
There are exactly two callers — `crates/talaria-mcp/src/socket.rs:25` and `crates/talaria-shell/src/control.rs`
— and both change by naming the module. `tests/e2e/harness.py` mirrors the path expression in Python
rather than importing it, so it is unaffected; its docstring already says why.

**The two headers that misdescribe the crate.** `lib.rs:1-14` says clients "(the `talaria-mcp` stdio
proxy today, the distributed-mode client later) speak newline-delimited JSON", and `control.rs:1-4`
calls itself "the in-process precursor to the distributed protocol". Both were reasonable when
written and both are now wrong in the same way: the distributed client speaks a **binary multiplexed
WebSocket** and shares this crate's *vocabulary*, not its transport. Rewrite both. The matching claim
in `.claude/CLAUDE.md` is 05-11's, so that the documentation closeout has one owner.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| an untrusted byte stream → a decoded wire value | The first place a hostile peer's bytes become a typed value, and the last place a structural lie can be caught cheaply |
| the human input channel → the agent tool vocabulary | Two different parties with two different privileges; a shared enum would let one reach the other |
| a refusal → an attacker's model of the server | Two refusals that differ are two bits the attacker did not have before |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-11 | Denial of Service | malformed wire input crashing or wedging the decoder — an unknown tag, a short header, an absurd tile geometry, a not-a-number coordinate | medium | mitigate | Every decode returns an optional value and every field is required; a short slice, an unrecognised version, a zero-sized tile and a tile that exceeds its declared frame are four separate refusals with four separate tests. This is the MCP-05 posture, applied to a new wire before the wire has a listener |
| T-05-04 | Elevation of Privilege | the agent tool vocabulary becoming reachable from the human input channel | high | mitigate | `Command` gains no input variant and the view control message carries no `Command` — both asserted by source criteria returning 0. This is expressed as an absence in the type rather than as a runtime check, which is the same shape `ChromeRect`'s own refusal takes and the reason it has survived three phases |
| T-05-05 | Information Disclosure | a refusal telling a caller which tabs are the human's | high | mitigate | The server's refusal message carries no reason at all, following the established rule that all refusals are one expression. A viewer that attaches to a Me tab and a viewer that attaches to a tab that does not exist receive identical answers, so the channel is not an enumeration oracle for the human's own browsing |
| T-05-15 | Tampering | replay of a captured input message within a connection | low | mitigate | The sequence contract — strictly increasing per connection, non-increasing dropped — is documented here in one place so the two ends cannot disagree about it; the enforcement is 05-06's and the cross-connection case is TLS's (05-04) |
| T-05-10 | Information Disclosure | the frame header leaking more than the frame | medium | accept | The header names a tab id, a geometry and two sequence numbers. It carries no URL, no title and no owner, so a frame in isolation says nothing about *which page* it shows beyond its pixels. Accepted as the minimum a client needs to place a tile correctly |
| T-05-SC | Tampering | package installs | n/a | accept | No dependency change. This crate's two dependencies are unchanged; every crate involved was audited in `05-RESEARCH.md` § Package Legitimacy Audit and 05-01 landed the phase's one addition |

ASVS level 1; block on high. Both high-severity items are mitigated **within this plan** and both are
mitigated structurally rather than by a check: the tool vocabulary is unreachable from the input
channel because no type connects them, and the refusal is uninformative because it has no field to
be informative with. Each is asserted by a source criterion returning 0, which is the shape this
project used in Phase 3 to pin that no MCP tool reaches the download opener.
