<objective>
Make the browser able to advertise an identity it did not bind, without letting it bind a wider one —
and put the certificate somewhere that is not this repository.

Purpose: `04-.../deferred-items.md` handed this phase an obligation in as many words: *"Phase 5 must
not enable a non-loopback bind before that lands."* Phase 4 shipped without TLS **because** it stayed
on loopback, which is OAuth 2.1 §1.5's explicit exception — and the exception is narrower than the
Phase 4 shorthand suggests. It covers loopback *redirect URIs*. The general rule, that every OAuth
URL the authorization server and resource server expose uses the secure scheme, has no locality
carve-out at all. A tailnet name is not loopback under either reading.

D-05-03 answers it the cheapest conformant way: Tailscale Serve terminates TLS with a
daemon-managed certificate and proxies to a loopback service, which is its only supported proxy
target and exactly what this browser already binds. **The bind host stays a constant.** D-04-04's
structural guarantee — that a wider bind is not a value this program can carry — is preserved
untouched, and certificate renewal leaves this repository entirely, which matters more than it
sounds: a long-running server that built its TLS configuration once at startup would happily serve
an expired certificate on day ninety-one.

The real work is a seam that does not exist yet. Four security-critical strings — the canonical
resource identifier, the issuer, the four endpoint URLs and the DNS-rebinding host allowlist — all
derive today from one `bound` read off `listener.local_addr()`, the socket itself rather than the
configured value. That single-source discipline is the pattern to preserve, and the temptation is to
break it: four `format!` calls that each learn about the advertised host separately would be four
places to disagree. Worse, the obvious shortcut — read the advertised host from the request's `Host`
header — hands a local page the ability to make this browser advertise an authorization server
somebody else chose. And `refuse_page_originated`'s `Host` comparison must learn the advertised name
or **every** proxied request is refused.

Output: one advertised-identity value threaded the way the bound address already is, a validated
configuration key that still cannot express a bind address, the secure scheme on every published
OAuth URL, and an executable script that stands the proxy up and takes it down without touching this
node's three unrelated live mappings.
</objective>

**Read `05-01-SPIKE.md`'s recorded header set before writing a line of this plan's code.** The spike
observed what a Serve-proxied request actually carries. Two outcomes change this plan's shape:

- If the proxy forwards `Host` as the **tailnet name and port**, the allowlist must learn it, and the
  layer that refuses a misaddressed request must admit exactly two names.
- If the proxy rewrites `Host` to the **loopback target**, the allowlist needs no change at all, and
  this plan's `http.rs` half shrinks to nothing while its `oauth.rs` half stays exactly as specified
  — the metadata documents must still publish the advertised URL, because that is the URL the client
  used and a client that fetched a document naming a different address would reject it.

Write for the observed case, and record the other in the SUMMARY as the case that was not taken.
If the spike recorded `A2: REFUTED`, **stop and say so**: this plan must then be re-planned onto
`05-RESEARCH.md`'s Option 2 — an exposure enum with a certificate precondition plus in-process

`canonical_resource`'s own doc comment already argues the discipline this plan must preserve: RFC 8707
audience validation compares byte for byte, so *"this function is the only place it is constructed. A
second construction site would be a way for a token to validate against one spelling of this server
and not another."* Everything this plan adds obeys that sentence. `05-RESEARCH.md` Pitfall 8's warning
sign is literal: **a second construction of a scheme-plus-host string anywhere in `oauth.rs` is the
failure.** Introduce one advertised-identity value and thread it; do not add four parameters.

**The configuration key, and the shape that keeps D-04-04 intact.** `RemoteAccessConfig` gains one
optional field carrying a full origin — scheme, host, optional port, and nothing else. It is
**not** a bind address and cannot become one: nothing reads it when binding, the bind host remains
the module constant used at exactly one place, and `from_json`'s existing `bind`-key refusal stays
byte-identical, including all three of its tests. Say that in the field's doc comment, because the
adjacency is exactly the thing a later reader will misread.

Validation, at load, following `from_json`'s question-mark-on-every-field discipline:

- the scheme is the secure one, **unless** the authority is the loopback literal with a port, which
  is the one case the specification's exception covers and the one case a developer testing locally
  needs;
- the authority is non-empty and carries no user information;
- there is no path, no query and no fragment — **including a bare trailing slash.** Refuse it rather
  than normalising it away: a normalisation is a second spelling, and a second spelling is exactly
  what byte-for-byte audience comparison cannot survive;
- anything else logs a warning naming what it saw and refuses, which returns nothing from `from_json`
  and therefore leaves the whole remote-access block at its default — **off**. That is the same
  direction and the same shape the `bind` key already takes, and the existing doc comment already
  states the rule: failing closed is the only direction this key may degrade in.

**With the key absent, nothing moves.** The advertised identity falls back to the bound address with
the insecure scheme, which is exactly what Phase 4 publishes today. That is what lets
`tests/e2e/http_transport_test.py` and `tests/e2e/oauth_flow_test.py` pass **unmodified**, which the
validation map requires and which is the only honest proof that the default path did not shift.

**`harness.py`'s seeding helper is where this surfaces in Python.** `write_agents`' `audience`
argument is compared byte for byte against the canonical resource, and its docstring already says so.
It gains one sentence: when a suite configures an advertised URL, the audience it seeds is built from
*that*, not from the loopback address. No existing suite configures one, so no existing suite
changes.

**The script, not the recipe.** `~/.claude/CLAUDE.md` forbids writing code inline into
documentation — referenced executable scripts instead. Standing up Serve is machine-level state
`tailscaled` holds and nothing in git records, so it gets `scripts/tailscale-serve.sh`, with an up
and a down mode. Three constraints, each of which is a real failure this node can actually suffer:
it operates on **one named port and refuses any other**; it captures the full mapping list before and
after and refuses to proceed if the port it wants is already in use by something else; and it
**never invokes Funnel**, which is the public-internet variant and would expose a process holding a
credential vault and a logged-in browsing session to the open internet. `05-RESEARCH.md` rejects
Funnel outright and asks that the refusal be explicit so it is a named non-option rather than an
unconsidered one.

**This node, as it actually is** (verified 2026-08-21; re-verify at execution, the Tailscale facts
carry a 7-day validity): three live mappings — `:8443` proxying `http://127.0.0.1:5678` for an
unrelated service, `:9446` and `:9447` proxying two others. **Use `8449`.** MagicDNS is on with
suffix `tailcd3cc6.ts.net`, and `CertDomains` reports `thinkpad.tailcd3cc6.ts.net`, so Serve can
front a real certificate.
