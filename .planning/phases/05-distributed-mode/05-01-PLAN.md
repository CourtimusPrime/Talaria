<objective>
Land the one dependency this phase needs, with `Cargo.lock` treated as the load-bearing artifact
`CLAUDE.md` says it is — then spend the rest of the plan settling the assumption that decides
whether D-05-03's exposure story is buildable at all.

Purpose: two things have to be true before 05-04 and 05-05 can be written honestly. The first is
that `axum`'s WebSocket feature costs what `05-RESEARCH.md` measured — exactly one added package,
`tokio-tungstenite 0.29.0`, whose sibling `tungstenite 0.29.0` this tree already carries through
`servo-net` — and that `primeorder` survives the resolution. That pin exists **only** inside the
committed lockfile; nothing in `[workspace.dependencies]` expresses it, and a fresh resolution takes
`0.14.0` final, which stops satisfying the trait bounds `p256`/`p384`/`p521 0.14.0-rc.14` are
written against, failing the build with an error that names none of the cause.

The second is assumption **A2**. D-05-03 puts Tailscale Serve in front of a loopback listener and
keeps `BIND_HOST` a constant — but Serve has a documented history of WebSocket-upgrade regressions,
and if it will not proxy an upgrade this phase falls back to a widened bind plus in-process rustls
and inherits certificate renewal. 05-04 also needs a fact only observation can supply: **which
`Host` a Serve-proxied request actually carries.** `refuse_page_originated` compares `Host` against
the bound address; if Serve forwards the tailnet name, every proxied request is refused until the
allowlist learns it, and if Serve rewrites `Host` to the loopback target, the allowlist needs no
change at all. Those are two different plans. Do not guess which.

Output: a `Cargo.toml`/`Cargo.lock` pair that builds with the locked flag and the pin intact, a
written A2 answer with observed headers, and this phase's `deferred-items.md` opened.
</objective>

**The pin, and the inherited procedure.** `Cargo.toml`'s header block (lines 15–33) already states
the `primeorder` constraint, the failure mode and the recovery command
(`cargo update -p primeorder --precise 0.14.0-rc.14`). `SPEC.md:98` says the same. CI builds with
the locked flag, and `.github/workflows/lockfile-audit.yml` is the scheduled job that resolves from
scratch and prints the diagnosis. Phase 4's 04-02 established the procedure this plan inherits
verbatim: **edit the manifest by hand, let a metadata resolution update the lock, inspect the diff,
back the edit out on rejection.** Never the automatic add subcommand, never a whole-tree update.

**What `05-RESEARCH.md` already measured, and what is left to confirm.** The research ran exactly
this procedure on 2026-08-21 against edited manifests in this working tree and restored the lockfile
byte-identical afterwards (`md5sum` `354ddad3f4e45c6aef8a58d39af1b30d` before and after). It
observed:

```

  Adding tokio-tungstenite v0.29.0
```

with three feature-edge additions (`base64`, `sha1 0.10.7`, `tokio-tungstenite` under `axum`) and
`primeorder` unchanged. **Re-observe rather than trust it** — the research is a snapshot, the
lockfile is the authority, and the whole point of this task is that the assertion is made against
the tree as it stands.

`axum 0.8.9` is already resolved in this tree through `rust-mcp-axum`, and `http.rs` already uses it
by name as `rust_mcp_axum::axum::*`. Adding it as a **direct** dependency unifies onto that same
node — the research's resolution run produced no second `axum`. Declaring it directly is what lets
`http.rs` write `axum::extract::ws::WebSocketUpgrade` without going through the re-export, and it is
also honest: this workspace uses `axum` deliberately now, not incidentally.

**What is deliberately not landed here.** The `talaria-client` workspace member. A `members` entry
naming a directory that does not exist makes `cargo metadata` fail outright, and 05-07 is the plan

finished creating makes this plan's own locked build race against it. 05-07 lands the member, the
client's manifest and the client's own dependencies in one edit.

**Tailscale, as it actually is on this node** (checked 2026-08-21, and re-check at execution — the
research put a **7-day** validity on every Tailscale claim):

- MagicDNS is on, suffix `tailcd3cc6.ts.net`; `tailscale status --json` reports
  `CertDomains: ["thinkpad.tailcd3cc6.ts.net"]`, so Serve can front a real certificate.
- `tailscale serve status` reports **three** live mappings, none of which this phase may disturb:
  `:8443` proxying `http://127.0.0.1:5678`, `:9446` proxying `http://100.118.105.121:3456`, and
  `:9447` proxying `http://100.118.105.121:9001`. **The spike's own mapping must use a distinct
  port** — use `8449` — and must be torn down in the same task.
- The global rule in `~/.claude/CLAUDE.md` binds local dev servers to **40000–40999**. The spike's
  throwaway echo server uses a port in that range. Serve proxies to it on loopback, which is
  `tailscale serve`'s only supported proxy target and exactly what Talaria already binds.

**Why the spike is a cargo example and not a scratch script.** It has to compile against this
workspace's real resolved dependency graph — that is the whole point of running it after Task 1
rather than in isolation. `.claude/CLAUDE.md`'s rule that throwaway scripts do not live in the
repository is satisfied by the file not surviving the task, which is the same accommodation 04-02
made and recorded.

**A2's second output is 05-04's input, and it is the more valuable half.** Even a clean `CONFIRMED`
on the upgrade is not enough. Record the **complete header set** a Serve-proxied request arrives
with: the `Host` value verbatim, whether an `Origin` header is present (a proxy that added one would
break every client, because `refuse_page_originated` is the outermost layer and refuses any
`Origin`), and every `X-Forwarded-*` and `Tailscale-User-*` header with its value. `05-RESEARCH.md`
names the identity headers as threat T-05-08: they are trivially spoofable by any local process
connecting directly to the loopback port, so they are never a boundary — but knowing they exist and
what they are called is how a later reader avoids reaching for them.
